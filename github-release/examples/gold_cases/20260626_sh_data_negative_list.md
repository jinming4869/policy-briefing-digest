# Gold Case: 上海数据出境负面清单首单备案

## Metadata

- Column: 政策法规发布（制度落地案例）
- Topic: 数据出境负面清单
- Source Type: 微信公众号（网信上海）+ 官方PDF（负面清单管理办法/清单/实施指南）
- Regulator / Publisher: 上海市网信办、上海市数据局
- Industry Context: 游戏/互联网公司数据出境合规
- Business Scenarios: 海外发行用户数据、跨境客服工单、支付记录、广告归因
- Date: 2026-06-26（首单备案日），2026-04-24（负面清单发布日）

## Final Version (用户定稿)

#### [**上海市网信办、上海市数据局发出全市首张数据出境负面清单备案结果通知书**](https://mp.weixin.qq.com/s/Q4k_aJLExeUoVX5aEf0ucg)

6月26日，爱特思亚太企业管理有限公司（Inditex集团亚太总部，运营Zara等品牌）通过上海市网信办、上海市数据局数据出境负面清单备案审核，取得2026年4月上海发布数据出境负面清单管理办法及配套清单后的全市首张备案结果通知书。该企业涉及跨国订单处理、客户沟通与供应链协同，其会员信息出境原需向国家和省级两级网信部门申报数据出境安全评估；依据负面清单新规，仅需向省级网信部门完成个人信息出境标准合同备案。在静安区数据跨境服务中心前置指导下，企业提交材料当日即完成区级初审。此前静安区已累计举办4场政策宣贯会，覆盖企业100余家，此次首案为同类跨境运营企业提供了完整流程参照。

> **解读：**本次首单备案溯源于2024年国家网信办[**《促进和规范数据跨境流动规定》**](https://www.cac.gov.cn/2024-03/22/c_1712776611775634.htm)确立的一般规则：企业向境外提供100万人以上个人信息，须向国家网信部门申报安全评估，审查周期通常数月。2026年4月上海市网信办与数据局联合印发[**新版负面清单**](https://www.cac.gov.cn/wxzw/sjzl/sjcjfmqd/A09370806index_1.htm)，在商贸领域将会员管理场景的安全评估门槛从100万人提至1000万人，100万至1000万人区间改为仅需个人信息出境标准合同备案。爱特思亚太的会员信息量级恰好落在这一放宽区间，合规路径因此从国家和省级两级审批简化至省级备案。对游戏公司而言，当前上海负面清单未覆盖游戏行业数据场景，出海用户数据出境仍适用2024年的通用门槛。但负面清单管理办法第20条明确"一地制定、多地适用"，若后续任何自贸区将游戏或消费互联网纳入清单，上海注册的游戏企业即可适用对应的放宽门槛，海外发行涉及的账号、支付和广告归因等数据有望获得同样幅度的合规减负。

## Why This Version Is Better

1. **合规变化描述精准**：用"从国家和省级两级审批简化至省级备案"替代"从安全评估降级为标准合同备案"，描述的是企业实际省了什么，而不是合规类型的正式名称。
2. **法条引用干净**：`2024年国家网信办《xxx规定》确立的一般规则`，不做括号嵌套、不写第X条。
3. **单一推力**：游戏公司段只保留"一地制定、多地适用"一个核心方向，删掉了实操指南、例外条款和尾注。
4. **首句开门见山**：`本次首单备案溯源于……`直接叙事，不写"本事项属于……不宜写成……"。
5. **非焦点数据不展开**：不罗列4行业9场景29子类109数据项，焦点是执法细节而非清单内容。

## Reusable Rules

1. 当事项涉及法条引用时，超链接提供出处，正文不嵌入法条编号和日期括号。
2. 企业合规变化用"省了什么"描述，不用合规类型名称变化。
3. 对游戏公司的建议只保留一条推力，删旁支。
4. 解读首句以本次事项为主语直接叙事，不用否定句纠偏。
5. 制度落地案例写清上位制度发布时间和主体，用门槛对比说明实际变化。
6. 非焦点数字（如清单涵盖的行业数量）不展开，避免引导读者误读重点。
7. 括号内的行业子分类若非本条焦点，直接删除。

## Anti-patterns Avoided

1. AI 纠偏口吻（`本事项属于……不宜写成……`）
2. 法条引用噪声（括号套括号 + 第X条）
3. 合规标签变化代替实际受益描述
4. 多推力游戏公司建议
5. 箭头式政策链条
6. 非焦点数字罗列
7. 解读段尾注式补充（`需注意……`）

## 方法论笔记（本次撰写中学会的）

### 读者视角
写完解读后问自己：如果我是企业法务，看完这段我知道接下来要做什么吗？如果不能回答，说明仍在"描述政策"而非"给出判断"。

### 具体举例
不用"例如某类数据"的抽象概括。用可感知的场景："一款出海手游有200万海外用户，其注册邮箱、设备ID和支付记录若传输至境外服务器进行归因分析，按现行规则触发安全评估"。读者不需要知道所有可能性，只需要一个可类比的案例。

### 比较前置政策
制度落地案例必须说明相比前置政策文件是"照搬执行"还是做了调整（门槛数字、适用范围、流程简化程度）。本次案例中，负面清单将安全评估门槛从100万提至1000万，是实质调整而非照搬。

### 合规路径优先选择
当涉及安全评估/标准合同/认证三条路径时，指出当前场景下哪条最便捷、哪条最保险。本次案例中标准合同备案最便捷（省级备案即可），安全评估最保险（两级审查）但最耗时。

### 上位法与下位清单交叉比对
不满足于"政策报道"，拿到下位清单原文（PDF/DOC）后与上位法逐条比对准入门槛差异，精确到具体数字。这比任何二手解读都可靠。
